# TangentAtlas.Web

The Tangent Atlas website, www.tangentatlas.com: the landing page, sign-up and sign-in (through Microsoft Entra External ID), and the signed-in pages. ASP.NET Core 10 with Blazor server-side rendering, deployed to Azure App Service on Linux by `.github/workflows/deploy-production.yml` on every push to `main`.

The ledger behind the product is [TangentAtlas.LedgerService](https://github.com/tangent-atlas/TangentAtlas.LedgerService), generated by [Bellerophon](https://github.com/bellerophon-dotnet/bellerophon).

## Running it

```
dotnet test
dotnet run --project src/TangentAtlas.Web --launch-profile https
```

Sign-in needs the external tenant's two identifiers (`IdentityProvider:Authority`, `IdentityProvider:ClientId`); without them the public pages work and nobody can sign in.

### Reading the ledger as the signed-in person

With the `Ledger` settings as well (`Server`, `Scope`, `CertificateThumbprint`), the signed-in page shows the person's own tenant, live: each account's worth, return, volatility and Sharpe ratio, its value at each close, and its holdings. The site signs people in with a code instead of an ID token alone, redeems it with its certificate (in the current user's store, private key not exportable: nothing secret is stored) for the person's access token, delegated `Ledger.Read` only, and reads the ledger with it. The ledger decides what the person may see; a person with no tenant sees the page as before. Without the `Ledger` settings the site signs people in exactly as before.

On a developer's computer:

1. TangentAtlas.Platform's `Deploy-EntraApplications.ps1 -SkipWebApp` gives the Website registration `Ledger.Read` and a development certificate, and writes all the settings to `%APPDATA%\TangentAtlas\website.json`.
2. TangentAtlas.LedgerService's `tools\Start-LocalLedger.ps1 -MarketHistory` runs the ledger at http://127.0.0.1:5180 with real sign-in; `tools\Set-LocalJoe10.ps1` loads the Joe 10 paper account and makes the test person its user.
3. `dotnet run --project src/TangentAtlas.Web --launch-profile https`, then sign in at https://localhost:7062 as the test person.

The token cache is in memory: after the site restarts, the next visit signs the person in again (silently while their session at the identity provider lasts).

### Live pages

The dashboard, investments and account pages follow the ledger as it changes, without reloading. Every part of them
that shows the ledger's data is part of the live view model, the frame included (an account's name in the title bar and
the browser tab): the signed-in pages run in Blazor's interactive server mode, layout and all, prerendered and then
connected to the site, which re-renders them when the person's data changes. Moving between them stays on the same
connection. The public pages (`Components/Pages/Public`) are static: `[ExcludeFromInteractiveRouting]`, so an
interactive page that links to one loads it in full.

- **A Replica per person.** The site keeps a Replica of the person's tenants (`Ledger/LiveLedgers.cs`), generated here
  exactly as the ledger generates its own Primary: the `Bellerophon` package, the ledger's model (the `AtlasLedger.Model`
  package, which carries its `bellerophon.json` and the types it names) and `<BellerophonRole>Replica</BellerophonRole>`.
  So the website and the ledger move to a new model together; a mismatch is refused (426).
- **Kept current by the generated sync client.** One per tenant: a snapshot of the tables the pages read
  (`LiveLedgers.Tables`, plus their parents), then long polls for the rows changed since, each request with the person's
  own token. No controller per page and no view model on the server.
- **Shared, then let go.** Every page the person has open uses the same Replica; it keeps running for
  `Ledger:KeepAlive` (five minutes) after the last one closes, so moving between pages starts from what is here.
- **View models are queries** (`Ledger/LedgerProjection.cs`): accounts, holdings and values, with market value multiplied
  here by the ledger's own formula (`Valuation.MarketValue`) from the quantities and prices it sends.
- **Deployment.** WebSockets on (TangentAtlas.Platform's `Deploy-CorporateWebsite.ps1`); one instance.
